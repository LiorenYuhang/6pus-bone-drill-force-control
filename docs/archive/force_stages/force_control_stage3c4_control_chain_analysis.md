# Stage 3C.4：任务空间力控链分析与最小修正

2026-11-04。输入为 Stage3C.3 `20261104_120323` 的既有真实记录。本轮全部离线，**没有打开串口、没有硬件写入、没有 Mode/Tare/Pause 操作，hardware_write_count=0**。未修改 Position/Torque，未 commit/push。

**结论：没有发现参考力重复相加、g/N 重复换算、软件 ID 排序错误或解析雅可比公式错误。独立有限差分、有限位移虚功与 FK 检查通过。发现并修正了分配器使用混合单位原始条件数作奇异判断的问题；实际实验姿态离该边界很远，此修正不改变本轮力分配，也不是已证实的失败根因。**

当前能确认的直接原因是：实际六轴力没有建立分配器所要求的增量，ID3 行程先到保护边界。为什么原生轴向力响应不足或反向，物理根因尚未由已有数据分离。不能把这种未知改写成“PID 公式错误”“雅可比错误”或“机械支撑一定有问题”。

## 1. PID 公式与完整调用链

当前配置 `force_pid.yaml: pid.output_mode=reference_plus_pid`，Kp=1、Ki=Kd=0。代码公式为：

```text
r = RateLimiter(target_z, 1 N/s, actual monotonic dt)
y = [J_s(q)^T · g_to_n(raw_g - hold_g)]_z
error = r - y
p = Kp * error
I = bounded, conditionally integrated Ki * error * dt
D = Kd * lowpass(-dy/dt)       # derivative on measurement
feedforward = r               # reference_plus_pid
u = clip(feedforward + p + I + D, -10 N, +10 N)
```

- `reference`：期望 Z 增量力经变化率限制后的参考 r，单位 N。
- `measurement`：相对本轮保持状态的实测执行器轴向力，经当前空间雅可比重建的 Z 分量 y，单位 N；并非已经独立测出的末端外部接触力。
- `error`：r−y，单位 N。
- `output`：**参考前馈加反馈修正后的最终任务空间增量力指令** u，单位 N；它不是单独的 PID 修正量，也不是六轴含保持值的绝对目标。

末条记录：`2.637517007 + (2.637517007 - 0.920047175) = 4.354986839 N`，恰好符合配置。对全部 178 个 PID 命令核对公式，最大差 `8.88e-16 N`。若选择 `pid_only`，Kp=1 时才是仅输出 error，但本轮没有选择该模式；不能擅自把它改成 error 来修复尚未证实的错误。理想内环 y=u 时，参考前馈+P 可给出 y=r；只用 P 且 Ki=0 则静态 y=Kp/(1+Kp)·r。实际内环尚不满足该理想关系。

`force_pipeline.py` 仅执行：`wrench[2]=pid.output_n` → `allocate(wrench, pose)` → `hold_n + allocated_delta_n`。后续没有再加 reference。函数另一次 `allocate(gravity=0, pose)` 只是取得 J 并验证几何，没有把零分配或参考再次加进输出。原始单位转换和 Node/Child SI↔native 传递也未形成第二个乘法比例；实际物理 TX 与保存的每轴整数 g 逐项一致。

±10 N 限制的是完整任务增量 u（含前馈），每轴 ±14.709975 N 限制的是 `hold_n+delta_n`，500 g/s 作用于转换后的电机绝对目标。保持力只加一次，反馈保持值只减一次。此分层与本轮架构一致。前馈令未建立测量时 u 接近 2r，确实增加输出，但这是已配置的控制律，不是重复叠加缺陷；是否适合实际原生力环要靠后续实验判断，不能在本轮擅自改增益。

## 2. 独立雅可比推导和验证

### 坐标、编号与适用条件

软件配置的执行器顺序为 ID1～ID6，数组索引为 `motor_id-1`。几何 YAML 第 i 对锚点就是 J 的第 i 行。底座锚点/平台局部锚点（mm）为：

| ID | 底座 a(x,y) | 平台 b(x,y) |

| 2 | −38.637033, −10.352762 | −27.500000, 0 |
| 3 | −28.284271, −28.284271 | −13.750000, −23.815699 |
| 4 | +28.284271, −28.284271 | +13.750000, −23.815699 |
| 5 | +38.637033, −10.352762 | +27.500000, 0 |
| 6 | +10.352762, +38.637033 | +13.750000, +23.815699 |

模型杆长 L=84 mm，平台半径 27.5 mm。q 是沿底座 +Z 的滑块位置（m），不是固定长度斜支杆 L；执行器伸缩量的微分等于 dq，而固定斜杆的长度微分为 0。raw steps 增大映射为 q 增大，HOME 映射仍为 `0.05 + (steps−1000)*0.000025 m`，没有使用曾经错误的 raw×meters_per_step 作 FK。

任务位姿 `[x,y,z,roll,pitch,yaw]`，m/rad，旋转 `Rz(yaw)Ry(pitch)Rx(roll)`。空间速度为 `[v_x,v_y,v_z,ω_x,ω_y,ω_z]`，ω 在底座坐标，线速度指动平台原点速度；广义力为 `[Fx,Fy,Fz,Mx,My,Mz]`，N/Nm，力矩关于动平台原点。这里的“空间”不把线速度改为关于底座原点的另一套 screw twist 定义。

令 `s_i=p+R b_i-a_i-e_z q_i`，刚杆约束 `s_iᵀs_i=L²`。微分得到：

```text
s_iᵀ(δp + δθ_B × Rb_i - e_z δq_i) = 0
δq_i = [sx/sz, sy/sz, 1, (Rb_i × s_i)ᵀ/sz] · [δp,δθ_B]
δq = J_s δx
W = J_sᵀ F_q,    F_q = solve(J_sᵀ, W)
```

成立条件是六个传感器力经过符号/比例处理后，确实代表与 +q 共轭的执行器广义力；不是直接把斜支杆张力、ADC 或未经动态/外力分离的读数混入。原生 0x27/0x2C 同单位、有符号编码已知，**传感器相对机械 +q 的作用/反作用方向及每轴安装仍不能只凭协议证明**。

### 独立性

新增离线脚本不调用分配器的有限差分或欧拉速率转换来生成参照 J：

1. 用 SciPy 独立构造 R，直接刚杆几何闭合式 `q=pz−sqrt(L²−dx²−dy²)`。
2. 对平移分别作中心差分；对转动使用底座旋转向量左乘 `exp(±δθ_B)R`，避免把 Euler 角差当空间角速度。
3. 对同样扰动再调用已有 IK 得到第二份差分，和解析 J 比较。
4. 用独立几何得到实际有限 δq，验证 `Fᵀδq=Wᵀδx`，而不是用同一个解析 J 同时分配和重建。
5. 把几何得到的 q 输入已有 FK，检查恢复的空间位移；同时用独立数值 J 重建解析分配结果。

实际起始位姿、末条同步位姿以及 10 个随机邻域非零姿态，共 12 个位姿；每位姿 12 组随机小扰动，共 144 组有限位移虚功试验。平移和转角使用不同尺度（约 1e−7 m、1e−6 rad）；另扫 1e−5、1e−6、1e−7、1e−8 的差分步长观察截断与舍入误差。

| 检查 | 最大误差 |
|---|---:|
| 解析 J 对独立几何中心差分 | 8e-11 |
| 解析 J 对 IK 中心差分 | 6.74e-11 |
| 解析分配→独立数值 J 重建（六种纯输入） | 6.72e-09 |
| 有限位移虚功差 | 1.82e-16 J |
| 几何位移→FK 恢复最大分量误差 | 1.18e-08（平移 m／转角 rad 分量） |

FK 误差按各分量报告，不把 m 与 rad 的混合数值拿来作物理误差范数。验证证明当前**模型内部导数和对偶关系正确**，不证明同一套几何参数已在实机上独立标定。Force 的 analytical FK/IK 源文件及几何 YAML 与 Position、Torque 对应文件逐项比较相同；复用了已有实现，没有重新开发 FK/IK。YAML 仍标记 `pending_final_assembly_confirmation`，实际安装尺寸/编号是否另有现场校准记录，本轮没有找到可据此独立确认的材料，未擅自改参数。

### 条件数与确定的软件修正

实际起点原始 cond(J)=290.175317，包含 m/rad 尺度，不能据此直接判断病态。用特征长度 Lc=0.0275 m 定义 `J_normalized=J·diag(1,1,1,1/Lc,1/Lc,1/Lc)`，即对 `[v,Lc·ω]` 作一致长度尺度，得到 cond=11.391304。178 个实际同步位姿的归一化条件数范围 `[11.389850809293689, 11.39169583315493]`，没有接近奇异边界。Lc 是模型平台半径，不是任意调到“通过”的值。

原 `allocate()` 虽计算归一化值，却用原始 cond/min_sigma 作拒绝决定。现改为使用归一化 cond 和最小奇异值作决定，保留原始数值作诊断，异常文本明确标注两者；既有数值阈值保留。没有改 J、solve、原力限幅或控制律。本轮所有实际位姿修正前后均不触发奇异，因此这项缺陷**不是 Stage3C.3 已证实的失败原因**。

## 4. 逐周期 ID、符号、单位与时间检查

核对所有 183 个周期 ×6 的实际 0x27 TX：电机 ID、顺序、有符号目标与保存向量逐项相同。再从原始 RX 完整解析 1098 个目标写应答，按返回 motor_id 归入数组，位置及力与 tracking/保护快照不符数为 0。协议 StatusFeedback `data[6:8]` 是 signed i16 的 g，`data[8:10]` 是独立 ADC；无 abs、重复取反、ADC 误用或数组错位证据。

g→N 仅用集中式 0.00980665，方向均为 +1；保持和增量在 N 域正确相加。对全部命令分配重建为 PID 输出的最大差 8.88e-16；反馈重建与保存测量差 0 N。正向目标最终整数 g 与期望总 N 的最大差 0.004893 N，小于半 g 名义换算 0.004903325 N，符合量化。包含零 PID 首周期时最大差 0.049618 N，来自已知启动限速，不是 g/N 错误。

Fixed-Lag 使用 q/f 同一事务、同一端点和 alpha。用保存的真实端点独立重算 178×6 次插值：力差 0 g、位置差 6.94e-18 m。命令循环起点与测量参考相差 29.921～29.988 ms（节点实际取时与循环起点有几十 µs 差异），符合 30 ms 设定。参考/限速器按当前 monotonic 实际 dt 更新、测量按过去同步时刻计算，是因果反馈延迟，不是位置与力用了不同时间。

**分析时不能把同一 tracking 行中新写命令后的 `raw_feedback_g` 与写入前的 `measured_z_n` 当作同一物理时刻比较。** 本报告用 command_context 的 aligned_* 和 measurement_ns 比较 PID；实时电流保留各自 latest RX 时刻，不伪造同步电流。插值端点间隔 11.999～67.333 ms，控制周期最大 61.791 ms，说明存在一次明显周期延长；它增加反馈滞后/时变采样，是可能的响应贡献因素，但没有数据证明它导致了 ID3 的方向性位移，不能把通信抖动写成根因或自动升级为新运动门禁。

Torque 的现有 `SixAxisPositionDrive.command()` 与 Force 的限速均为 monotonic 实际 dt：`previous+clip(target-previous,±rate*dt)`。位置 0.017 m/s 与力 500 g/s、任务参考 1 N/s 各自独立。没有 Position 三阶整形器误入本轮力控链。Force 当前反复 N↔g 的消息编码往返是单位域转换，不是连续两次把同一原始数值乘 0.00980665。

## 6. 为什么有横向位移

纯 Z 广义力不是纯 Z 位置命令。当前只有 Z 力 PID，其余五维任务力命令为 0；没有对 X/Y/姿态作位置保持。只有在实际六轴力跟上分配，且外力、约束、阻尼/刚度等条件满足时，才可能形成预期运动。即使广义力完全纯 Z，耦合质量/刚度、支撑约束也可能产生横向运动；本轮实际反馈本身已经偏离纯 Z。

本轮最终 `delta_q=[0,0,0.200,0.025,0,0] mm`，明显不是纯 Z 位移需要的六轴共同等量伸长。用**独立数值 J**逆解这一实测位移，线性预测 ΔXYZ=`[+0.402710,−0.299328,+0.039334] mm`，与非线性 FK `[+0.402877,−0.299084,+0.037303] mm` 接近。其中 ID3 的 +0.200 mm 单独贡献约 `[+0.460284,−0.266068,+0.034959] mm`，ID4 的 +0.025 mm 贡献约 `[−0.057574,−0.033261,+0.004374] mm`。这解释了**已观测不均匀行程如何对应横移**，不是解释各轴为什么没建立目标力的物理根因。
