### 帧格式核对（仅说明，未发送）

读一个寄存器：`55 AA 04 ID 31 Addr_L Addr_H 01 CS`；写一个寄存器：`55 AA 05 ID 32 Addr_L Addr_H Value_L Value_H CS`。校验和为除帧头外各字节累加的低 8 位（7–10 页）。

厂家 ID1 示例：

```text
0x25=3：          55 AA 05 01 32 25 00 03 00 60
0x27=1000 g：     55 AA 05 01 32 27 00 E8 03 4A
连续写 [3,0,1000]：55 AA 09 01 32 25 00 03 00 00 00 E8 03 4F
```

连续写中间的 **0x26 是输出电压寄存器**，在力控模式下无用，厂家示例填 0；不是速度、滤波或力控参数。一次报文包含同轴模式和目标，仍不代表固件承诺无中间状态，也不代表六轴同时生效。

## 4. 与现有代码相关的切换风险

1. **不是零载机构。** 当前 ID1、ID3、ID6 的力幅值分别约 36.8、60.6、68.6 N，且方向不同。切换后减少承载、改变原有力平衡和刚度，都可能使支链或动平台运动。未知旧目标、统一 0 gf 或统一很小的目标均不能当作无扰起点。
2. **现有初始化不匹配当前基线。** `ServoCore.initialize()`（`j14_process_uart.py:316`）和 `enter_force_mode()`（344 行）默认标量 `initial_force_g=0`；传输层（307 行）对六轴使用同一值。不能表达六轴当前不同大小、不同符号的候选初始目标。默认目标力限幅 ±1500 gf（约 ±14.71 N，393 行）也覆盖不了上述三轴当前读数的幅值。不能只提高限幅来处理这一矛盾。
3. **六轴非原子。** 当前方法按 ID1→ID6 逐轴切换，先切换的轴可能已运动，其他轴仍为位置模式。厂家未规定“必须同时”，也未证明任何固定顺序对本机构安全。方法二只能缩短同轴模式/目标的报文间隔，不能消除混合模式阶段。
4. **部分成功时状态未知。** 代码失败后不重试写入，调用一次 stop/Pause（`j7_six_axis_servo_transport.py:339,939`）；但已成功的模式不会自动回滚，失联轴也无法保证收到 Pause。不能宣称“全有全无”或“绝不容许单轴维持输出”。
5. **模式确认不充分。** 写 ACK 带状态而非 0x25 读回；当前 `mode_3_active=True` 是软件标志，ready 中的 `control_mode=3` 由该标志生成（`j14_process_uart.py:326–342`），不是实测六轴模式。传输方法还创建了空 `configs` 列表却未追加逐轴记录（320–347 行）。下一阶段必须逐轴读 0x25=3，并保留目标力读回/状态；单有 ACK 不足以确认目标或物理平衡。
6. **退出未实现 Mode 0 交接。** `exit_force_mode()`（351 行）仅调用 `stop_adapter` 并清除本地标志，没有写 0x25=0，也没有准备当前位置目标。Mode 0 会追踪 0x29；旧位置目标可能引起突跳。不能把该函数称为“已安全返回位置模式”。
7. **零力超时不等于安全保持。** `candidate_force()`（179 行）在目标超时后选择六轴零力，厂家并未承诺这对受载平台安全。Parent lease 超时会调用 stop（644 行），但串口断开时，Pause 可能无法送达；设备端自主断线策略仍未知。
8. **当前硬件许可和 dry-run 不能完整约束写入。** 初始化或自动 `enter_force_mode(0)` 可能先执行，周期分支的 `hardware_write_enabled` / `is_hardware_qualified` 检查在后（378–407 行）。而 `is_dry_run=True` 时跳过该检查，410 行仍无条件调用 `send_force_cycle()`；不能把 active+dry-run 当作无写入运行方式。本阶段因此没有启动正常 Child。这是下一阶段使用该路径前需要处理的具体写入风险。

现有 Stage 3A 文档中“0x26=速度/滤波”“六轴全有全无”“零力安全保持”等文字不构成厂家或实机证据；本次以此文纠正解释，不修改旧控制实现。

### 进入前与部分成功处理

1. 先取得厂家关于目标保持、正负目标、允许力范围、首次输出和 Pause 的明确说明，并确认本机型号/固件。现场完成机械支撑、空间和独立硬件急停确认。
2. 在支撑可靠且工况明确时读取当前六轴模式、力、位置、旧 0x27/0x29 和必要的故障/限值。当前只读诊断只允许 0x25/0x2C，不在本次临时扩大它的串口访问范围。
3. 准备六轴各自的初始力和必要位置交接目标，确认目标/反馈符号、标定和寄存器含义一致。当前力基线只能作为评估候选，不能证明写同值就无扰；不使用默认零力。
4. 若采用手册的同轴连续写模式+目标，仍要由原有单一 UART 所有者执行，逐轴记录 ACK/实际模式和力/位置变化，限定混合模式阶段的处置。没有厂家的寄存器提交语义或机械条件，不能选择并宣布一个“安全顺序”。
5. 任一轴失败、模式读回不符或机构出现异常，停止继续切换/输出，不盲目重试或继续切其他轴。使用经确认有效的既有停止接口；若通信失效或停止不确定，由现场人员按已验证的独立硬件停止和承载方案处置。不要自动将剩余轴切到 Mode 3，也不要盲目回写六轴 Mode 0。
6. 只有六轴分别读回 0x25=3、目标和状态符合预期，才能称为“全轴已进入 Mode 3”。仍须另外观察支链/平台位移和受力，模式读回本身不是安全证明。

### 退出并返回 Mode 0

1. 在已确认的机械承载方案下停止继续改变参考，并根据厂家明确的 Mode 3 Pause/目标保持语义安排交接。不能默认 Pause 能托住平台。
2. 为每轴准备实测当前位置对应的 0x29，而不是旧位置/HOME/零位；由厂家确认从 Mode 3 交接到位置模式的可用写法、寄存器生效顺序和负载保持方式。手册允许连续写模式及目标，但没有证明无扰退出。
3. 交接后逐轴读取 0x25=0、目标/实际位置、力及故障，并观察机械状态；通信异常或负载保持不确定时不宣称退出完成。位置模式名义值和本地布尔标志都不能代替这一确认。
