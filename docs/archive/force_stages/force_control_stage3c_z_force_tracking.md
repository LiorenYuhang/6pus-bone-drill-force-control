## 真实闭环链及通信

本轮专用入口仍由既有 `ServoCore`/UART Child 唯一持有 `/dev/ttyUSB0` 和 OS 串口锁，调用正式 `TaskSpaceForceControlNode`。实验入口直接交付真实反馈并逐周期调用原节点回调，复用 Bridge 的字段填充函数；没有另开串口，也没有重写 PID 或雅可比算法。本轮没有重新验证独立 Parent→IPC→Bridge 三进程的持续运行性能。

真实 `0x27` 写应答内的 StatusFeedback 提供各轴当前位置、实际力、电流、ADC、故障；位置与力来自同一响应及同一接收完成时间。每轴原始时间戳进入原 `FixedLagJointSynchronizer`，30 ms 对齐后才执行 FK、`Jᵀ f`、PID 与分配。1106 次 PID 对应 1106 个唯一反馈序列，没有重复消费；没有用命令值替代测量。时间戳是主机接收完成时间，不是设备采样时间。

`g → N → Jᵀ → PID(N) → 分配(N) → 每轴 N 限幅 → N→g → 原一阶 g/s 限速 → int16 → 真正写入0x27`。正式记录包括分配前 N、限幅后 N、发布目标 N 和最终 g。分配方程最大分量残差为 **2.22e−16**（按相应 N/Nm 分量）；未触发下游限制的周期，整数编码后 Z 指令重建误差最大 **0.02713 N**。2 个周期触发下游限速，未扩大限幅。

正向段实际目标写入范围 −14～+10 g，反向段 −36～−12 g。正向目标并不要求每个瞬间所有执行器目标为正：带参考前馈的 PID 还会纠正当前实测力高于参考的误差。所有实际编码保留有符号方向。

正式轮共 **7818 次请求/完整应答匹配**，无未匹配应答、遗留未响应请求或记录到的超时异常。根据物理 TX 与完整 RX 日志相关得到的主机接收延迟：最小 **1.291 ms**、均值 **2.893 ms**、最大 **52.977 ms**。共有5条超过10 ms，其中2条超过50 ms，不能概括为全程低延迟：

- 22:46:01.617，ID1 `0x32/0x27` 至主机读到完整帧 52.977 ms；同批 ID2 为 52.065 ms。
- 上述两条在同一次主机 RX 读中出现，不证明电机计算本身耗时53 ms；本次没有独立分离 USB/主机调度/设备延迟来源。
- JSONL `tx_write_duration_ms` 为串口写调用耗时，`host_tx_to_rx_drain_ms` 为 TX 到状态收集完成的耗时，均不冒充设备采样周期。

正式轮真实写帧：**7392 = 7380条0x27 + 6条Mode3连续写 + 6条Mode0同帧重锚定**；Tare=0、Pause=0。写操作不重试。串口已释放。

## 载荷、测量能力及下一步

历史装配Tare前ID3/ID6读数−6143/−6972 g名义约−60.24/−68.37 N。独立单机存在过零点偏置，六轴各自的无载偏置/实际预载分量没有独立标定；不能直接证明实际机械载荷等于这些名义数值，也没有取得消除潜在超额定迹象的独立证据。本次询问后用户要求继续小幅实验；此不确定性和原始数据仍保留，不能将Tare后的小值、零电流或本轮未触发停止条件作为额定载荷合规证明。

当前±0.5 N任务目标对应近似每轴±0.083 N的参考增量，低于该规格表列的单轴1 N分辨率。实际小g变化与整数回读存在，并不自动证明可分辨相同幅值的物理力。本轮没有可靠外部反力/外部测力性能证据，不能声称已验证受载力跟踪。

**可以进入有界调参与响应原因定位，但当前不能宣布Stage3C正反向跟踪达标，也不应直接扩大目标或使用更激进增益。** 先以本轮数据定位零目标残差、原生小力死区/摩擦/反馈滤波和任务目标相对测量分辨率的问题，并在有可控反力时验证；本轮未单独确定这些因素的物理根因。Ki=0不会主动积分消除静差，但不能因此直接断定加入积分就能解决传感器和工况限制。
