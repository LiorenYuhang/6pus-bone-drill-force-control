2026-11-04。本轮只读历史硬件数据、修改 Force 软件及离线验证。**未连接串口，hardware_write_count=0，未执行 Tare/模式切换/电机指令，未修改 Position/Torque，未提交或推送。**

## 结论及证据边界

**确定的主要问题是执行闭环能力没有随姿态算法一起迁移。** Base 反向补偿目标正确，原角度 PID 也实际运行；但它后面新增的 `0.2 Nm/rad` 示例 P 输出只生成约 0.04 Nm、每轴不到 1 N 的目标增量。真实执行中四轴电流仍为 0，只有 ID2/ID4 出现电流，六轴没有形成目标位姿所需的协同运动。不能把“复用 Position 的姿态参考”当成“已经复现 Position 电机位置伺服的执行能力”。上一版软件实现的不足正是在这里。

**确定的独立阻塞是运动范围不匹配。** 本轮实际末端姿态目标经 IK 需要最大约 231 steps 的执行器变化，原保护为 6 steps。即使重新整定增益，这两个范围也不能同时满足。本轮没有扩大保护。

没有发现可证明的 Base 整体反号、轴交换、雅可比转置写反、重复 N/g 转换或 0x27 编码错误。发现并修正了日志时序归属错误，并针对实际发生的退出额外位移增加故障轴优先退出。**这两项软件修正没有被称为已解决真机主动稳定。**

原生力环为何在小误差下无可观测电流/位移，仍不能仅凭这一次约 0.8 s 的明显扰动，区分厂家内部动作阈值、摩擦/自锁、机械支撑反力及传感器特性各自的贡献。不能把“固定 100 g 死区”写成厂家已确认结论，也不能盲目取反某轴力值。

## 2. Base 到补偿目标是否正确

Position 和 Force 的核心关系一致：

```text
q_rel = q_initial^-1 * q_current
R_mechanical = C * R(q_rel) * C.T, C=Rz(+90°)
R_ff = R_B.T * R0
error_world = Log(R0 * R_platform_world.T)
residual_world = Position_M2_PID(error_world)
R_command = R_B.T * Exp(residual_world) * R0
```

R0 是本轮实际捕获 FK 姿态；R0=I 时就是 Position 原式。广义力与 Jacobian 同在底座系，旋转误差用 SO(3) 对数，未对 Euler 角直接相减。

最后一个有效命令：Base Pitch=-11.220°，补偿目标 Pitch=+11.803°，实际 FK Pitch=+0.132°。**补偿方向和目标幅度都存在，未被 ±0.5°裁成小动作。** ±0.5°只是 Platform 残差 PID 的修正预算，Base 反向前馈不受它限制。

用 Base IMU、Platform IMU 和 FK 检查闭合关系 `R_B*R_FK ≈ R_platform_world`，明显扰动段残差约 0.064°～1.163°。它不支持整体 90°轴交换或整体反号，但也不足以证明所有安装角、内部 IMU 延迟和六轴实际映射均已校准正确。不能用有限差分通过替代实物支链/传感器方向确认。

## 3. PID 输入输出及为何补偿不足

当前实际两级控制是：

```text
Position M2角度PID -> 姿态参考（rad）
e_pose = [p_ref-p_fk, Log(R_command*R_fk.T)]
Delta_W = Kp_pose*e_pose              # 本轮位姿 Ki=Kd=0
Kp_pose = [10,10,10,0.2,0.2,0.2]     # N/m；Nm/rad
```

不是 `0.04 rad` 被误标为 Nm；是明确乘了一个未经力执行实验整定的 Nm/rad 增益。没有再叠加第二次参考力。真实力用于内部原生力环和上层重建/监测，**没有额外的上层力矩误差积分去补偿原生力环偏差**。

以下时间相对 Base SO(3) 首次达到 2°，都使用当周期实际同步数据：

|---|---:|---:|---:|---:|---:|
| 0.000 | -2.057 | +2.307 | +0.124 | +0.00762 | -0.00320 |
| 0.100 | -4.048 | +4.400 | +0.124 | +0.01492 | -0.00183 |
| 0.301 | -7.083 | +7.558 | +0.105 | +0.02602 | +0.00742 |
| 0.503 | -9.883 | +10.487 | +0.105 | +0.03627 | +0.00290 |
| 0.808 | -11.220 | +11.803 | +0.132 | +0.04084 | +0.01353 |

位姿 Pitch 误差约 0.2042 rad，乘 0.2 得 0.04084 Nm。平移增益 10 N/m 意味着 1 mm 误差仅产生 0.01 N；本轮位置偏差对应的平移修正甚至只有约毫牛量级。这些例值不能被当作与原位置伺服等效的控制增益。

## 4. Jacobian、分配方向与实物约定

雅可比映射对象是**竖直滑块坐标 q**，不是斜连杆的伸长量。正确关系仍为：

```text
q_dot = J_spatial * [v_B,omega_B]
W_B = J_spatial.T * f_slider
Delta_f = solve(J_spatial.T,Delta_W)
```

在 8 个本轮实际位姿，通过几何/IK 独立有限差分检查，最大元素误差约 7.28×10⁻¹¹。无量纲条件数约 11.390～11.392，没有本轮进入数值奇异的迹象。原有纯 X/Y/Z、三个纯力矩和有限虚功测试继续通过。

所有分配向量、原始 TX 电机 ID、对应 RX 和状态缓存逐轴匹配，软件顺序为 ID1～ID6，没有发现下标置换。原始符号保持，不取绝对值；厂家 g 与 N 只在边界转换一次。

末周期的六轴理论位姿需求（相对当周期实际 q）约 `[+55.8,+229.6,+164.2,-58.8,-223.0,-161.7] steps`；实际力目标增量为 `[+53,+52,-18,+54,-79,-62] g`。例如 ID4 的目标力为正而 IK 所需位移为负，**不能单凭这一点判定力符号错误**：纯广义力分配同时满足六个广义力约束，力不是速度/位移指令，实际运动还受惯性、摩擦、支撑和其他轴作用。把力方向强行改成 IK 位移方向会改变所需广义力。

这也说明纯 wrench 控制不会自动等同于六轴位置参考跟踪。物理 ID/安装极性仍需受控实物验证；本次没有借软件一致性宣布六个力传感器方向已独立标定。

## 5. F_hold 到 0x27 与电机真实响应

## 7. 本轮软件修正

### 正确标记已发命令和下一次计算

旧 `tracking.control_sequence` 是写入后的下一次计算序号；与本行已发目标的来源序号在 2,967 条有效上下文中都不同。若按这一列直接拼接，会把未来计算误归到旧目标。

`stage4_experiment.py` 新增明确的 `sent_command_index`、`sent_command_feedback_sequence`、`sent_command_measurement_ns` 和 `next_command_*`。旧列保留并标注 NEXT 语义，历史数据不改。本次分析按上下文和原始 TX 正确重建，不依赖错误拼接。

同时记录原 IMU 字段实际入库时刻、接受有效性及捕获的姿态/四元数参考，不再只能用回调结束附近的记录时间近似恢复。部分 H30 消息不刷新另一个缺失字段的时间。

### 减少故障轴等待逐轴退出的时间

历史 ID4 在保护触发后约 63.5 ms 才轮到 Mode 0 写入，锚点已从 +7 增到 +13 steps，最终 +14 steps。现有 `transition_to_position_mode()` 增加可选 `priority_motor_ids`；Stage 4 在行程超限时优先处理超限轴。

保留同一帧 Mode 0+当前位置、每轴模式/目标读回、不重试、不自动 Pause；返回锚点始终按 ID1～6排列。默认调用仍按原顺序，正常主动稳定仍全部 Mode 3。本次没有修改原通信协议或退出帧。

**软件排序通过，不等于真机额外位移已消除。**它不能使切换原子化，也不能保证所有移动轴瞬间停止；新增顺序仍需下一次小幅受控实验验证。此项只处理已发现的退出延迟，不冒充主动稳定控制律修复。

### 未盲改的部分

没有翻转轴力符号、修改 Jacobian、提高 PID 增益、加摩擦补偿跳变、增加未经验证的力矩积分、扩大 0.15 mm 保护或重复 Tare。当前数据不支持把任意一种这样的改动宣布为确定修复。

## 9. 下一次真机实验应回答什么

本轮不执行以下动作。

1. **先不手动旋转 Base，验证力执行层。**沿用实时 F_hold、全部 Mode 3，对 ID2/ID4 及未动作轴做短时、渐变的正负小增量，记录真实力误差、电流和 q；示例分级为 ±50、±100、±150 g，保留现有每轴绝对限幅、500 g/s 和位移保护，出现动作即停止扩级。机械支撑和退出处置需适合这一动作；不得用手抵住平台。新故障轴优先退出也只在此小幅试验中验证，不直接用于大扰动挑战。
2. **先恢复执行层的位姿跟踪能力，再调姿态残差。**保持原 Position 姿态参考和 Jacobian，依据上述真实力/电流/q响应整定位姿→力 PID，而不是继续把 0.2 当成已有硬件依据。真实力矩误差目前只监测；是否需要额外补偿必须基于原生力环响应和符号确认，不能直接叠加高增益积分。若选择复现 Position 更直接的执行方式，可采用同一 IK 的 q_ref 配合 Mode 3 外位置/速度 PID，最终仍只写 0x27；这是下一版控制设计选择，不是本轮已验证的等效方案。
3. **完整 10°～20°前解决行程定义冲突。**本轮真实参考最大需求约 231 steps，无法在 6 steps 内实现。必须明确可安全使用的控制行程或调整实验目标；本轮没有权限/依据擅自放宽保护。不能再按同一配置重复大扰动并期待 Position 效果。

当前可以据此开展有明确问题和判据的小幅执行层实验；不能报告 Force 已具备 Position 的三轴大幅主动稳定性能。
