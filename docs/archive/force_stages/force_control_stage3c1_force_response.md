## 2. 当前真实反馈及单位链

开始前通过同一UART Child读取0x25、0x27、0x2A、0x2B、0x2C、0x2F和完整StatusFeedback：

- 六轴最初Mode0，电流/故障码均0，旧目标分别为`[-9,-10,-9,-10,-9,-9] g`。
- 直接0x2C为`[-17,-187,-66,-30,20,0] g`；紧邻的StatusFeedback为`[-17,-187,-66,-30,18,0] g`。两个查询时刻不同，ID5相差2 g，未强行使之相等。
- `protocol.py`在状态载荷`data[6:8]`以little-endian、signed=True解析`force_g`；`data[8:10]`为独立ADC。寄存器0x2C读回应答也按int16保留符号。这些是本次物理请求/应答，不是旧JSON、命令值或软件默认零。
- 保存的有效配置中`sensor_zero_g=[0]*6`、`actuator_bias_n=[0]*6`、`direction=[1]*6`。没有重复软件减基线，N转换只通过集中式`0.00980665 N/g`名义比例。力传感器硬件Tare与该单位转换分开。

本轮PID未启动，不能声称这些顺序快照已经通过Fixed-Lag形成PID测量点。每轴StatusFeedback本身的位置和力来自同一响应；源时间为主机接收时间，不是设备采样时刻。新的原始值随时间变化，不是沿用昨天的缓存基线；传感器独立物理精度仍未标定。

## 4. 实际执行与停止

真实执行时间11:00:40.195～11:00:41.603。六轴逐轴进入Mode3，实际逐轴读回均为3、初始0x27均为0 g。随后开始原生零目标保持，第一批六轴0 g命令的真实状态响应即触发已有位移监测：

恢复过程中又变化1 step，未把退出描述为零延迟或无位移。ID3观察到17 mA峰值，其他轴峰值0 mA；均未触发500 mA电流条件。所有观察到的故障码为0。

**PID执行次数为0。** 动作发生在原生0 g目标时，不能归因于外层PID增益、PID限幅或雅可比分配。ID2初始反馈−187 g而目标0 g，存在设备力参考误差，原生控制产生了驱动输出；Mode3零力目标并非位置锁定命令。尚不能由这一次记录确认误差变化的物理根因或认为已建立稳定零目标状态。

没有继续±5 N，没有进入±10 N，也没有加大位移边界再次尝试。正式节点、反馈同步链与原控制算法被保留，但本轮在它们产生PID输出之前停止。
