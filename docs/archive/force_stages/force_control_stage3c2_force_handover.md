# Stage 3C.2：六轴 Mode 3 当前实测保持力交接

2026-11-04，Asia/Shanghai。**已完成软件修正及一次 2.506 秒真实零增量保持；六轴目标读回均与本轮实时 0x2C 保持力一致，六轴全部退出 Mode 0。未重复 Tare，未启动 PID，未发送 ±5/±10 N 阶跃。**

## 原因与协议依据

上轮 `results/stage3c1_force_response/20261104_105738/hardware_writes.csv` 明确记录六个进入帧均为 `[3,0,0]`；实验入口显式调用 `enter_force_mode_with_handover([0]*6)`。ID2 的实际 TX 是 `55 aa 09 02 32 25 00 03 00 00 00 00 00 65`，因此 0x27 的 0 g 是主机主动写入，不能归因于已证实的固件自动清除。

厂家 V2.0.4 手册印刷第 23 页（PDF 第 25 页）“方法二”明确允许从 0x25 连续写模式 3、0x26=0、0x27 有符号目标。实现采用该方式，在同一轴的同一报文携带完整保持目标；未使用先切换到 0 g 再补写的方法。**这不是六轴硬件原子切换，也不能证明电机内部寄存器提交在某一时钟周期原子完成。**

Mode 0 下可写入 0x27 的单电机既有记录在 V2 报告中；独立写 0x25 时旧 0x27 是否始终保留、内部生效延迟仍未单独验证。本次无需依赖这些未知行为，也没有用新实验试探它们。

## 实现与单位链

- `j14_process_uart.py`：通用“当前状态”交接始终读取本轮真实 0x2C，保存独立六轴参考。曾经做过硬件 Tare 也不能使该入口自动选择六轴 0。历史专用 Tare 实验入口保留，当前实验未调用。
- `j7_six_axis_servo_transport.py`：逐轴发送 `[3,0,F_hold_u16]`，读取 0x25 与 0x27，两者都正确才继续下一轴。目标不符与切换失败都进入已有恢复流程；已进入 Mode 3 的轴以当前 0x2A 和 Mode 0 同帧重锚定，未切换轴不写，禁止自动 Pause。目标确认前已记录轴进入 Mode 3，确保目标错误也会恢复该轴。
- `six_axis_force_drive.py`：新增纯软件保持值验证/限速起点初始化接口，保留有符号 int16；保持值超出绝对 N 限幅时拒绝，而非裁剪成另一个载荷目标。
- `force_pipeline.py`：独立保存不可由 PID reset 重采集的保持向量。反馈为 `g_to_n(raw_g-hold_g)`，当前空间雅可比转成增量广义力 N/Nm；原 PID 输出任务增量 N，原雅可比分配产生六轴增量 N；最后 `hold_n+delta_n` 在绝对 N 域限幅，N→g 后经过原一阶实际 dt 限速和有符号编码。预测施加增量也减去 hold，防止抗饱和计算混入保持力。
- `force_control_node.py`：提供当前保持力初始化接口；reset 保留保持参考及限速起点。原始反馈和校准轴向反馈话题仍保留原语义，任务空间重建反馈在初始化保持参考后表示相对变化；诊断显式增加 hold 和 relative 字段。不得再叠加 sensor_zero/static bias/gravity 补偿，避免重复扣除。
- `stage3c_experiment.py`：在同一现有 UART Child 读取、交接并将同一向量交给正式 Force 节点。`hold_only` 仅持续写保持目标，PID 不执行；其它后续 PID 工况默认也采用当前实测保持参考。未新增 UART 所有者、同步器、PID 或分配算法。

原有 Kp=1、Ki=0、Kd=0、PID ±10 N、参考 1 N/s、每轴 ±14.709975 N、电机 500 g/s、位置参考 0.017 m/s 和 6 steps/0.15 mm 位移保护均保留。保持参考是操作增量定义，不是硬件 Tare，不是机械卸载，也不能用来绕过厂家额定力。历史 Tare 前读数与载荷关系的未解释部分仍保留，不据此假定机械预载已消失。

## 执行记录及实际结果

现场支撑、运动空间和独立急停沿用用户已有确认。启动前串口无占用，使用 `/dev/ttyUSB0`、921600、现有排他锁和维护模式 UART Child，启动阶段只读；dry-run、写授权和资格标志保持独立。六轴实际初始模式均为 0，初始电流/故障码均为 0。
