# 单电机原生力控与传感器清零实验

> 单位说明（2026-11-03 更新）：厂家原生力数据统一称为 g；算法采用 0.00980665 N/g 的名义克当量换算，后续可标定。本文仅修正单位文字，历史原始 JSON/JSONL、帧和数值均保持不变。

日期：2026-11-03，Asia/Shanghai。真实串口 `/dev/ttyUSB0`，921600 baud。

**结果：ID1 已短时进入真实 Mode 3，正目标 100 g 写入并回读成功；位移达到本次上限后已退出到 Mode 0。未找到公开的正式硬件 Tare 命令，未执行清零。未验证负目标力或无扰退出。当前不应将本次结果扩展为六轴力跟踪已可运行。**

## 授权、设备与执行边界

用户明确授权独立电机真实模式切换、厂家支持的清零和小幅力控，并确认电机可靠固定、无外部轴向负载、杆端运动空间安全、能够立即独立断电。

运行前未发现串口占用。使用既有 `UartBus`、`Motor`、协议编码/解析及 `SerialPortLock`；串口采用 `exclusive=True`，只有一个所有者。没有启动固定操作六轴的正常 UART Child，没有调用六轴广播或六轴 Pause。只读识别查询 ID1～254，仅 ID1 应答；这与用户说明的单电机连接一致，但不等于 UART 能识别同 ID 的重复设备。

运动阶段仅允许 ID1，并明确设置 `dry_run=False`、`hardware_write_enabled=True`、`is_hardware_qualified=True`。本次确认范围仅为现场已确认条件下、独立无载电机的小正目标测试，不代表六轴机构资格。所有请求重试数均为 0，所有原始请求/应答均记录。

## 厂家依据

依据本地《LAF 因时机器人微型伺服电缸（力闭环专用）LA 用户手册（电气）V2.0.4cn》，编号 PRJ-01-TS-U-007。以下采用印刷页码，PDF 页码加 2。

- 第 11～12 页寄存器表：`0x25=3` 为力控、`0x25=0` 为定位；`0x27` 为力控目标、单位 g、可读写；`0x2A` 为位置；`0x2C` 为实际受力值；`0x2D` 为 ADC，范围 0～4095。
- 第 9、11 页：状态返回中的力传感器值为有符号 16 位；这不等于厂家已经明确规定 `0x27` 的全部负目标语义。
- 第 21 页：Mode 3 动态调节位置以接近目标力。因此自由杆端没有外部反力时，不能期待正力目标靠静止自动实现。
- 第 22～23 页：正目标 1000 g 示例，以及从 `0x25` 连续写 `[3,0,F]` 的进入方式。本次使用相同格式的小正目标 100 g。
- 第 14～16 页：Mode 0 和目标位置 `0x29` 的写入机制。退出复用 Stage 3B-1.2 的当前位置重锚定顺序；厂家未保证受载切换无扰，本次对此进行了实际观察。
- **硬件 Tare：**检查完整手册文本、公开寄存器表及现有 Force 驱动，未找到正式的力零点命令、执行条件、保存或重新上电语义。`0x18` 是清故障、`0x1B` 是还原参数、`0x1C` 是保存参数，都不能当作 Tare。未试探未知地址，未写上述寄存器。

既有项目 README 标注 LAF50-024D，选型手册 V18.1 印刷第 29 页给出最大推拉力 50 N、堵转/最大自锁力 80 N、传感器范围 ±100 N。但本次没有独立读取铭牌或确认完整固件型号；这些参数不能代替该台设备的完整 Mode 3 目标范围说明。100 g 名义约为 0.981 N。

## 初始真实读取

只读阶段：18:59:14 起；状态采样时间为 18:59:21.399～18:59:22.214。

| 寄存器 | 实际读回 | 解释 |
|---|---:|---|
| `0x16` | `0x0001` | Motor ID1 |
| `0x25` | `0x0000` | Mode 0 |
| `0x27` | `0xFFFF` | 原有目标原始值；不能仅凭补码解释认定是有效 −1 g 目标或出厂默认值 |
| `0x2A` | 0 steps | 当前处于行程下端 |
| `0x2C` | `0xFCCE` / −818 g | 该次寄存器真实有符号读数 |
| `0x23` / `0x24` | 2000 / 0 | 读回行程上下限，未修改 |

随后 5 次真实状态反馈的力为 `[-811,-811,-827,-818,-822] g`，均值 −817.8 g，范围 −827～−811 g，总体标准差 6.242 g。位置均为 0，电流均为 0 mA，温度 30℃，故障码 0，ADC 为 1897～1898。

用户确认无外部轴向负载，但传感器读数没有接近零。该事实需要进一步区分零偏、内部预载、方向/标定和固件处理；不能把这些名义换算值直接认定为真实外部接触力或机械过载。此前六轴原始值与额定力的直接比较，尚不足以单独证明机械过载；也不能反过来证明任意目标写入都安全。

## 实际模式切换与小正目标测试

19:00:56 前重新读取初始状态：Mode 0、`0x27=0xFFFF`、位置 0、原始力 −811 g。未沿用旧 `0xFFFF` 目标；通过厂家连续写格式显式给出小正目标。

真实写入仅 **3 条 0x32 帧**：

| 时间 +08:00 | 操作 | TX 原始帧 | 实际确认 |
|---|---|---|---|
| 19:00:56.399180 | `0x25` 连续写 `[3,0,100]` | `55 aa 09 01 32 25 00 03 00 00 00 64 00 c8` | ACK 故障码 0；随后 `0x25=3`、`0x27=100` |
| 19:00:56.528083 | `0x29=22`，当前位置重锚定 | `55 aa 05 01 32 29 00 16 00 77` | ACK 目标位置 22、实际位置 23、故障码 0 |
| 19:00:56.531375 | `0x25=0` | `55 aa 05 01 32 25 00 00 00 5d` | ACK 故障码 0；随后 `0x25=0` |

对应完整 RX 及逐次读请求在原始 JSONL 中，未裁剪。

Mode 3 的 9 次状态采样中，位置为 `[0,0,2,7,8,10,15,17,21] steps`；力为 `[-811,-811,-811,-811,-811,-811,-811,-817,-821] g`。电流由约 137 mA 上升至最高 255 mA，故障码始终 0。

测试预设相对位移达到 20 steps 即退出，以及电流 >300 mA、温度 >50℃、非零故障码或通信失败即中止。实际在读到 21 steps 时触发位移条件，立即结束正目标测试并执行退出；未进行原拟的 +150 g 阶段。没有 Pause、没有负目标、没有持续追力或动态力轨迹。

**结论边界：**已经验证正目标协议被接收/读回，并观察到驱动输出与伸出运动；实际反馈没有跟踪到 +100 g。无外部反力和未解决的无载偏置使本次不能评价正力跟踪精度，也不能据此判定控制器失效。

## 退出与最终状态

按现有 `读0x2A → 写0x29当前位置 → 写0x25=0 → 回读模式` 执行，退出锚点为 22 steps，Mode 0 读回成功。刚退出时实际位置 24，之后为 `[24,5,0,0,0] steps`；最终电流 0 mA、故障码 0。

19:01:50 再次只读确认：

| 字段 | 最终读回 |
|---|---:|
| `0x25` | 0 / Mode 0 |
| `0x27` | 100 g |
| `0x29` | 22 steps |
| `0x2A` | 0 steps |
| `0x2C` | `0xFCD5` / −811 g |
| 电流、温度、故障码 | 0 mA、30℃、0 |

**模式退出已验证，但“无扰保持位置”未通过：**目标位置仍为 22，实际位置返回 0，存在退出瞬态和最终跟踪差。原因尚不明确，不能把 ACK/Mode 0 回读称为机械无扰退出保证。没有为了消除差值继续追加位置命令。软件只获得电机内部位置反馈，没有独立视觉或外部位移测量。

本次观察到 `0x27=100` 在 Mode 3→0 后仍可读到。只证明这一次切换后寄存器保留，不证明重入、断电或重新上电的行为。

## Tare、反向目标与待确认项

1. 公开资料未提供正式 Tare 接口，故没有硬件清零前后对比，也没有清零后断电重启实验；不能声明设备固件绝对不支持厂家私有清零。
2. 没有修改反馈或用软件减基线冒充硬件归零。软件零点不会自动改变电机内部 Mode 3 所用的反馈零点。
3. 未验证负目标。现有代码按 i16 补码编码，厂家状态反馈明确有符号，但 `0x27` 的负值方向、范围和固件支持仍需厂家确认。原有 `0xFFFF` 读数也不能作为负力可执行的证据。
4. `0x27` 的厂家单位为 g，工程按 g 名义换算；寄存器占 2 字节、小端。软件 i16 编码范围 −32768～32767 不是厂家允许的持续目标范围。本次仅验证 +100 g。
5. 厂家仍需明确：无载力读数的零偏/标定方法、正式 Tare（如有）的模式/无载/保存条件、Tare 是否改变内部力控零点、负力目标语义、完整允许范围、Mode 0 重锚定后回到行程下端的原因、重入/断联/上电时的目标与闭环状态。
