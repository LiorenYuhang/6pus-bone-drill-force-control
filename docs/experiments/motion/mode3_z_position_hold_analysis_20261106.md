# 2026-11-06：10 mm 上升后顶部保持超时分析与最小修正

原始实验：`results/z_position_motion/20261106_130621_472451/`。本轮只读分析原始记录，未启动真机；本轮 `hardware_write_count = 0`，不同于原实验报告中的 63390 次写入。

## 结论

**直接原因是位置收敛判据的浮点边界错误。** ID4 真实记录对应目标减实际位置为 2 steps，SI/IK 换算后的浮点误差却为 `2.0000000000004547`，严格 `<= 2.0` 比较失败，反复重置连续保持计时。不是上升轨迹没有到位，也不是程序缺少返回轨迹。

仅在这个比较上增加 `1e-9 steps` 的算术舍入容差后，同一批真实顶部数据在阶段约 **4.026687 s** 满足原有“稳定 1 s + 保持 3 s”的条件。这个结果只证明新判据将允许进入返回阶段；**没有新的真实返回运动，也不能推断修正后的物理返回轨迹已经成功。**

顶部前 14 s，各轴位置峰峰变化为 `[1,1,1,1,1,0]` steps，六轴速度估计均为 0。当前估计器在约 80 ms 历史范围内，位置跨度不超过 1.5 steps 时输出 0，因此**不能把速度估计为 0 解读为机构物理上完全不动**。

约 14.3 s，ID6 的编码器位置出现较大的短时变化，14～15 s 窗口峰峰值为 4 steps（0.1 mm），与非零电流、D 项和目标力变化同时出现。随后又有一次反向估计速度脉冲，5 个超阈值周期中，ID6 峰值为 +1.22054 mm/s，负向峰值约 −0.73324 mm/s。D 项峰值约 −6.103 N，PID 最终增量受原 ±4 N 限幅，力指令还受到原变化率限制。

这些是记录中可见的小幅调节，不能全部归为浮点误差；但编码器量化抖动与真实微动的比例没有外部测量，不能武断指定唯一物理来源。速度估计本身依照现有公式对可见位置变化作出响应，**没有证据需要为此次超时重写速度估计器**。它们发生在原本已经可以完成顶部保持之后。

## 判据失败的逐项定位

原要求为六轴位置误差均 ≤2 steps、速度估计均 ≤0.05 mm/s、FK Z 误差 ≤0.1 mm，连续满足 1+3=4 s；每次任一条件失败就清零计时。

| 条件 | 顶部失败周期数 | 解释 |
|---|---:|---|
| 原始严格位置比较 | 174 | 含真实超出 2 steps 以及浮点边界误判 |
| 消除舍入后的位置比较 | 43 | ID5 1 个、ID6 42 个；仍拒绝真实 3-step 误差 |
| 仅由浮点边界误判的位置周期 | 131 | ID4 有 138 个精确边界误判，其中 7 个同时存在其他轴真实越限 |
| 速度比较 | 5 | 均为后期 ID6，保持此检查 |
| Z 比较 | 0 | 始终通过 |

原判据连续全部满足的最长时间只有 **0.580255 s**，远小于要求的 4 s。修正后同一历史数据的最长连续满足窗口约 **14.273948 s**，首次满足 4 s 为顶部约 **4.026687 s**。不需要增加 20 s 超时，不需要把容差放宽到 3 steps，也不需要删掉速度判据。

## 为什么没有返回，以及最小修改

返回轨迹已经实现。原逻辑只有在 `top_hold` 连续满足判据后才把阶段设为 `return`；本次计时始终被误判重置，20 s 到达后抛出异常，转入既有故障恢复。故障路径不会自动执行返回轨迹，因此没有返回是这条分支的确定结果。

原实验随后执行一次每轴 Pause，再进行同帧 Mode 0 当前位置锚定。终止报告确认六轴 Mode 0，锚点为 `[1404,1397,1410,1409,1398,1402]` steps，位于顶部附近；不是初始位置。此处描述的是历史退出记录，没有读取当前实时机构状态。

本次生产代码只在 `z_position_motion.py` 抽出纯判定函数 `hold_sample_settled()`，将位置边界由 `<= tolerance_steps` 改成 `<= tolerance_steps + 1e-9`。额外量约合 `2.5e-14 m`，只覆盖计算舍入，实际 2-step 容差不变。PID 参数、速度估计、IK、200 s 五次上升/返回轨迹、力限幅与斜率、硬件保护、故障路径和 Mode 0 恢复全部保持不变。

该修正同时作用于起点、顶部、返回点的同一收敛比较，避免返回后再次被相同边界问题阻塞。完整软件流程仍是：实测初始位置 → 上升 10 mm → 稳定 1 s 后保持 3 s → 平滑返回初始位置 → 再次稳定/保持 → Mode 0。
