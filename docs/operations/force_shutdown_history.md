# Force 控制退出修复与手动恢复

> 2026-11-05 更新：下文保留最初修复时的边界记录；端点反馈容差、退出锚点及最新启动方式已按后续要求更新，见 [手动柔顺恢复当前说明](manual_recovery.md)。实测 −1/2004 不再直接按故障拒绝；反馈值与合法命令目标分开保存。

2026-11-05。本轮仅软件开发与历史数据分析，未打开真实串口，`hardware_write_count = 0`。用户已明确确认机构动力断电；这是现场确认，不是本轮设备测量。历史实验、原始帧均保留。

## 已确认的问题

Stage 5 / V2 把“正常运行必须 Mode 3”扩展成了“退出也禁止 Mode 0/Pause”。具体包括：UART writer 的 Pause 回调被置空；`mode3_only` 禁用了部分进入失败的位置恢复；Stage 5 字节白名单禁止退出帧；异常 finally 关闭 PID/串口但保留原生目标；目标超时可返回旧保持力或零力。短时间零电流、力匹配、关闭串口都不能证明之后不会运动。

真实历史数据直接支持这一风险：

- `20261104_174653_axes456/tracking.jsonl` 最后一批位置为 `[1053,1080,1049,1066,999,997]`。
- 351.639 秒后，`20261104_175411_axes456_decoupled` 读取为 `[1116,593,686,-1,186,997]`，六轴仍为 Mode 3。
- 两个时刻的 `0x27` **完全相同**：`[-222,-218,-200,-213,-181,-21] g`。后一次启动没有写入。

这证明两时刻位置不同且原生力目标残留。中间没有连续测量，不能据此单独证明每个时刻的运动、是否有人干预，或全部物理原因。

历史帧解析与来源见 [分析数据](../../results/force_safety_recovery_20261105/historical_position_analysis.json)。

## 新的运行与停止机制

正常控制仍为 Position 的姿态目标/IK → 六轴外部位置 PID → `F_hold + ΔF` → 集中式 N/g 换算 → 原一阶实际 dt 限速 → Mode 3 `0x27`。未更改 PID 增益、力限幅、坐标或运动学。

| 情况 | UART 单一所有者的处理 |
|---|---|
| 正常暂停、退出、Ctrl+C、实验完成 | 禁止后续正常命令；逐轴读取新鲜模式/位置；Mode 3 轴同帧写入 Mode 0 与当前位置；读回模式及目标，观察位置、电流、故障 |
| 目标流超时、反馈失效、通信错误、父进程租约超时/IPC 关闭 | 原有一次性逐轴 Pause 故障路径恢复；随后尽力执行同帧位置重锚定；不能确认的轴保留未知/失败状态 |
| 部分 Mode 3 进入失败 | 停止后续切换；复用原有仅恢复已切换轴的路径，不额外自动 Pause；不重试已失败或应答不确定的锚定写入 |
| ID4 类无效位置、2004 类超出锚定范围 | 不用 0、1000、2000 替代；其余轴可完成各自恢复，失败轴明确报告；整体不能标记停止成功 |
| 外部 PID 进程崩溃，但 UART Child 存活 | Child 的既有目标超时触发终止，不再回退旧力目标；父进程退出还由既有 IPC/租约处理 |
| UART Child 被 SIGKILL、NUC 崩溃、USB/总线不可用 | 软件无法保证命令送达，必须依赖独立硬件急停/动力切断；没有声称已解决设备端失联停车 |

退出后 `0x27` 原字可以保留，但确认 Mode 0 后它不再作为活动的力控目标。下一次 Mode 3 必须重新采集保持力并同帧覆盖，不能沿用旧字。

终止处理只能执行一次；`close()` 会调用它，已有故障锁存不会使恢复路径被跳过。进入失败已尝试的恢复不会在外层再重复写入。正常模式回切不是六轴硬件原子操作。

`force_shutdown.json`、Child 最终记录及实验结果保存各轴最终模式、原始位置、锚点、应答/错误、观察值。成功条件是六轴 Mode 0、目标锚点确认、位置接近锚点且观察窗口内稳定、电流正常、无故障。它是有限窗口的读回与位置保持确认，不是永久机械安全保证。Mock 结果带 `source=MOCK`，不能产生真实硬件停止通过结论。

ROS 主动稳定节点禁用/退出会请求既有 `/pus6/pause_all` 所有者接口；该接口仍异步，服务返回不是停机证明。重新使能需要明确复位并重新建立真实 Mode 3 交接。IMU 暂时缺失仍可冻结姿态目标并保留有效位置闭环；实际执行器控制失败不再被当作高层监测缺失忽略。

## Pause 的已知与未知

本地 V2.0.4 电气手册印刷第 29 页规定 `0x1A=1` 暂停当前运动，示例应答为 `0x32` 状态帧。现有 `J7StopAdapter` 逐轴、零重试发送，现已要求应答状态故障码为零才计入 ACK 成功。

手册没有说明 Mode 3 下暂停后的承载/制动行为、是否清除 `0x27`、断联停车时限和恢复条件；单电机 V2 也没有实测这些。不能把 Tare 的 `0x40` 异步完成机制套给 Pause，更不能把 Pause ACK 当作完成停车。本轮不发送 Pause，后续需要现场验证其物理效果。正常退出优先采用单电机和六轴已验证过的 Mode 0 同帧位置交接，而不是仅依赖 Pause。

## ID4 / ID5 及跨工程差异

- 保存的 ID4 `0x2A` 应答原始字确为 `0xFFFF`。寄存器读取显示无符号 65535，StatusFeedback 按厂家有符号 16 位定义显示 −1。二者是同一字节内容，不是两个位置。厂家是否将其作为特殊故障值未知；无论是负越界还是特殊值，都不能作为当前位置锚点。
- ID5 同次原始寄存器和状态都为 186，超出 Force 正常范围 200～1800，但在绝对命令范围 0～2000 内。恢复检查和正常运动检查必须区分。
- Position 的反馈容差为 −5～2005；但 HOME/PARK 分类要求全轴相符或都在合法命令范围，不能把容差当成任意当前位置运动授权。用户报告 `[1955,354,122,231,934,2004]` 中 2004 会导致混合/不可规划状态，故不能用 HOME=1000 伪造起点。
- Position、Torque、Force 均保持同一电机编号、步距、HOME 映射和协议字段。读取时刻、旧目标位置 `0x29` 与实际位置 `0x2A`、正常范围与反馈容差不同会造成表面差异。本轮没有找到这组最新用户读数对应的完整同时间跨工程帧，不能把所有差异归结为解析错误。

## 手动柔顺恢复程序

入口为 `force_manual_recovery`，脚本入口为 `bone_ws/scripts/force_manual_recovery.py`，配置为 `bone_ws/src/pus6_force_control/config/manual_recovery.json`。

仅离线检查（本轮已实际执行，不打开串口）：

```bash
cd /home/lyapunov/6pus_bone_drill_force_control
source /opt/ros/jazzy/setup.bash
source bone_ws/install/setup.bash
ros2 run pus6_force_control force_manual_recovery --positions 1955 354 122 231 934 2004
```

结果：ID6=2004 无法作为合法位置锚点，程序不会将它改成 2000 或 1000。最新六轴位置是用户报告，未在本轮重读。需在后续允许硬件读取后核实 ID4/ID6 的真实行程、反馈及参考，保留当前断电和机械支撑，不靠 Tare 或软件放宽掩盖它。

程序已实现的现场流程：

1. 在未来明确允许操作后，沿用 `ServoCore`、串口独占锁及现有协议；没有第二个 UART 所有者。不广播、不执行 HOME/PARK、不清零。
2. 读取各轴模式、实际位置、`0x2C`、目标力、电流与故障；进入前重新通过现有交接接口采集六轴真实保持力，并验证原绝对 N 限幅。
3. 保持空格键允许手动移动整个有独立支撑的动平台。通过已验证同帧 `Mode 3 + F_hold` 进入，不统一写零力。
4. 柔顺目标为 `F_hold − D·q_dot`，速度反馈用实际 dt 低通；增量默认限 ±0.5 N，500 g/s，原绝对限幅 ±14.709975 N。只是小幅速度阻尼，不做不可靠的外力放大，也不把固定保持力称为停车。该新柔顺律尚未实机验证。
5. 默认速度上限 2 mm/s、电流 200 mA、反馈间隔 0.2 s；初始位于正常范围外但仍在绝对范围内的轴只允许向内恢复，持续向外超过 2 steps 即终止；正常范围内轴不能移出 200～1800。不能据此保证机械端部绝不越界，独立硬件停止仍必需。
6. 松开空格后 0.75 s 内触发退出；`F` 完成、`Q`/Ctrl+C 停止；最长 120 s。终止时读实际位置，同帧逐轴锚定 Mode 0，确认后才报告位置保持。异常退出也进入统一终止处理。
7. 保存所有 TX/RX、六轴位置/实际力/目标力/电流及最终位置到 `results/manual_recovery/<时间>/`。无真实执行时没有最终实测位置。

下面是**后续现场用法，本轮未执行，当前 2004 steps 问题解决前不能直接运行**。三个既有硬件条件仍分别显式提供；`--hardware-qualified` 不是本报告授予的真机资格。

```bash
ros2 run pus6_force_control force_manual_recovery \
  --config bone_ws/src/pus6_force_control/config/manual_recovery.json \
  --execute --no-dry-run --hardware-write-enabled --hardware-qualified
```

程序利用实际六轴位置做既有 FK，再检查通往中间姿态的协同 IK 候选路径，检查分支回代和每个路径点的绝对行程。该路径只用于分析，不自动执行。FK 不收敛时不生成自动轨迹；人工恢复也不会将当前位置强制设成 HOME。六轴回到正常范围并完成锚定后，再评估是否适合由正式协同控制回到 HOME。
